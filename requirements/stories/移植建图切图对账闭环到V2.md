# 移植建图切图对账闭环到V2

状态: 规划中

## 背景与动机

机器人建图任务闭环（start→save→自动入库→激活→周期对账 map-align，MapModeTaskService 676 行）整条链路写死在 V1 nav_map 上，V2 完全没有对应实现。这是 V1 下线的最大阻塞项，也是本次重构最大单块功能移植。

## 角色与意图

As a 现场部署人员，I want 建图保存后自动生成 V2 地图并发布、切图后自动对账，So that 不依赖任何 V1 表完成完整建图部署流程。

## 功能描述

将建图/切图/保存/放弃/周期对账链路重写到 V2 模型：

- save_map 成功 → 机器人栅格 upsert 到 V2 地图（新图建 PUBLISHED 前草稿或更新既有图 grid）→ 自动发布
- 切图任务按 V2 地图执行，成功后当前地图基准切换
- 周期对账（map-align/map-sync SSE）改以 V2 PUBLISHED 地图为基准
- 前端 MappingPanel2 的 map-mode-tasks 调用全部改走 V2 端点

## 业务规则

- R1: 新链路只写 V2 表（map 系），禁止写 nav_map
- R2: 建图保存产生的地图必须走发布流程，未发布不可执行任务（术语表现状）
- R3: 对账语义保持：机器人当前图 ≠ 平台基准图时通过 SSE 上报 map-align 异常
- R4: RMS start/stop_mapping 闭环同步切换到新链路
- R5: 旧 V1 链路在本故事完成前保持可用（共存期双轨）

## 验收标准

- AC1: 仿真环境完成一次"开始建图→保存→自动生成 V2 地图并 PUBLISHED"全流程
- AC2: 保存的地图在 v2 编辑器打开，栅格与机器人侧一致
- AC3: 切换到另一张 V2 地图成功后，机器人侧图名与平台一致，SSE 无 map-align 异常
- AC4: 人工把机器人切到非基准图，60 秒内 SSE 收到 map-align 异常
- AC5: V1 链路全程未被调用（日志核对）

## 范围外

- 多机器人并发建图冲突策略（现状没有，不新增）
- V1 对账代码删除（属"下线V1地图前后端"故事）
