# 搭建共享内核与用户域试点

状态: 规划中

## 背景与动机

BC 搬迁需要先立模板：nav-common 共享内核 + 最小的 nav-user 域作为 walking skeleton，跑通四层包结构、MapStruct、Cmd/Query/DTO、RepositoryImpl、Swagger、nav-app 装配全链路，形成后续 BC 照抄的样板。

## 角色与意图

As a 开发者，I want 一个完整走通编译、启动、冒烟的最小 DDD 模块，So that 后续 BC 搬迁有确定可抄的模板。

## 功能描述

1. 新建 nav-common：ApiResponse（自 app 迁入）、BusinessException、ErrorCode 接口
2. 新建 nav-user 模块，按四层重组 users 能力：interfaces(UserController) / application(UserService、cmd/query/dto) / domain(User、UserRepository) / infrastructure(UserRepositoryImpl、mapper、UserMapstruct)
3. 新建 nav-app（或改造现 app）：装配、全局异常处理、component scan
4. 根 pom 收编新模块，旧 platform/app 中用户代码移除

## 业务规则

- R1: 严格按 AGENTS.md 模板决策（无 DO、Mapstruct spring 模式、XxxDTO、checkXxx）
- R2: 用户域对外 API 请求/响应结构零变化（URL、JSON 字段）
- R3: 领域行为迁移：密码校验、状态判断等逻辑从 Service 下沉实体（checkXxx）
- R4: 所有对外接口补 Swagger @Tag/@Operation/@Schema
- R5: nav-common 只放 ApiResponse/BusinessException/ErrorCode，其他一概拒绝

## 验收标准

- AC1: nav-common、nav-user、nav-app 模块存在，四层包结构齐全
- AC2: 用户登录/查询冒烟接口响应与重构前逐字节一致（除动态字段）
- AC3: `mvnw compile -DskipTests` 全仓通过，fat jar 可启动
- AC4: Swagger UI 可见用户接口且注解完整
- AC5: 模板要点（包结构、命名、Mapstruct 写法）回写 AGENTS.md 或 specs 补充说明

## 范围外

- 其他 BC 的搬迁
- 用户域功能增强
