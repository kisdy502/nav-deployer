# 迁移存量V1地图数据

状态: 已取消

> 用户决策（2026-11）：存量 V1 地图数据不做迁移，全部废弃。V1 表随"下线V1地图前后端"故事直接 DROP。

## 背景与动机

V1 地图下线前必须把库中存量 V1 地图数据迁移为 V2 多楼层模型，否则路线执行失去 V1 兜底后数据丢失。迁移能力已存在：`/api/v2/maps/migrate/{navMapId}`（MapMetaService.migrateFromNavMap）。

## 角色与意图

As a 现场部署人员，I want 库中每张 V1 地图都有等价的 V2 版本，So that V1 下线后地图、点位、路线仍可使用。

## 功能描述

盘点库中 V1 地图清单，逐张调用迁移端点生成 V2 地图，人工核对拓扑完整性（点位数量、路线段、坐标范围），全部确认后发布（PUBLISHED）。

## 业务规则

- R1: 迁移只读 V1 数据、只写 V2 表，不得修改 V1 记录
- R2: 每张迁移产出的 V2 地图须人工核对点位/路线数量与 V1 一致
- R3: 迁移后 V2 地图需发布（PUBLISHED）方可视为完成
- R4: 发现 migrateFromNavMap 缺陷（丢点/丢段/坐标漂移）时，修复缺陷单独立任务，不静默手改数据

## 验收标准

- AC1: 库中不存在未迁移的 V1 地图（迁移清单核对表存入 requirements/tasks/）
- AC2: 每张迁移产出的 V2 地图状态为 PUBLISHED
- AC3: 抽样 3 张地图在 v2 编辑器中打开，点位/路线渲染正常
- AC4: FOLLOW_PATH 任务用迁移后路线执行成功一次

## 范围外

- V1 数据清理（属"收尾装配并删除V1表"故事）
- migrate 端点的增强开发（缺陷驱动，单独立任务）
