# 重建实时栅格与机器人地图端点到V2

状态: 测试中

## 背景与动机

`GET /api/v1/nav-maps/live`（实时栅格）被 V2 编辑器复用（mapEditor2.ts），`/nav-maps/robot-maps`、`/import-from-robot`（机器人侧地图列表/导入）也是 V1 前缀。V1 下线前需在 V2 体系重建这些能力并改前端指向。

## 角色与意图

As a 地图编辑用户，I want 在 V2 编辑器中实时预览机器人栅格、查看机器人侧地图列表并导入，So that 全部地图操作不依赖 V1 端点。

## 功能描述

- nav 侧新增 V2 实时栅格端点（如 `GET /api/v2/maps/live`），复用 LiveMapCache（两代共享基建）
- 机器人侧地图列表与导入能力评估：V2 已有 from-live/import-zip 能力，仅补机器人侧地图枚举；导入若已被 from-live 等价覆盖则随 V1 消亡并在 story 中记录结论
- 前端 http2.ts 增加对应调用，mapEditor2.ts:217 等改指向 V2 端点

## 业务规则

- R1: 新端点遵循 docs/codeStyle/5-restful-api.md（URL 禁动词、连字符小写）
- R2: 响应结构与旧端点字段一致（前端只换 URL，不改数据结构）
- R3: LiveMapCache 逻辑不重复实现，一处缓存两处消费

## 验收标准

- AC1: `GET /api/v2/maps/live` 返回实时栅格 JSON，字段与旧端点一致
- AC2: v2 编辑器实时预览正常且网络面板无 /api/v1/nav-maps 请求
- AC3: import-from-robot 的去留结论写入本 story（保留则 V2 版可用，否则记录等价替代路径）

## 结论记录（AC3）

`/nav-maps/robot-maps` 与 `/nav-maps/import-from-robot` 的唯一消费方是 v1 建图面板（MappingPanel.vue），随"下线V1地图前后端"故事消亡，**不重建**。等价能力：机器人侧地图导入由 V2 `import-zip`（含 NativeMapClient installMap）与 `from-live` 覆盖；机器人侧地图清单在"移植建图切图对账闭环到V2"故事中按切图链路需要再评估。
