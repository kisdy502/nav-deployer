# 下线V1地图前后端

状态: 测试中

## 背景与动机

V1 独有能力已移植（建图闭环、to_waypoint、live 端点、RMS delete），存量数据经用户决策不迁移、全部废弃，V1 体系可整体下线：后端实体/服务/端点、前端 v1 编辑器与相关页面，并 DROP 四表。

## 角色与意图

As a 开发者，I want 移除全部 V1 地图代码路径，So that 代码库只有一套地图模型，降低维护成本。

## 功能描述

后端删除：NavMap/NavPoint/NavPath/NavPathEdge 实体、Mapper、Service、NavMapController/NavPointController/NavPathController/MapExchangeController、MoveTaskService 的 V1 兜底分支（TO_POINT pointId 校验、nav_path 回落）、MapAlignmentGuard V1 兜底、RmsMapService V1 兜底、MapModeTaskService 旧链路、migrate 端点与 MapsV2ManageDialog 迁移按钮。

前端删除：`/editor/:id` 路由与 EditorView、editor store、components/editor/*、api/{maps,points,paths}.ts、mapList store、HomeView 的 V1 地图区（切图下拉/部署引导/importFromRobot）。

## 业务规则

- R1: 删除为纯移除，不顺手重构 V2 代码（结构重构属后续 BC 搬迁故事）
- R2: move_task 历史数据中 point_id/path_id 的 V1 语义：保留原值不删数据，查询展示按现状容忍缺失（处理口径写入 tasks 文件）
- R3: FOLLOW_PATH 的 V1 回落分支删除后，找不到路线的错误信息须可判读（提示 V2 语义）
- R4: 前端仅做删除与指向修正，无 UI 改版

## 验收标准

- AC1: 全仓 grep 无 NavMap/NavPoint/NavPath（NavPathEdge）实体、Mapper、Service 引用（DDD参考代码 等非工程目录除外）
- AC2: v2 编辑器建图/编辑/发布/导出、to_waypoint、充电、FOLLOW_PATH 冒烟全部通过
- AC3: RMS mapping/change、mapping/get、任务派发冒烟通过（无 V1 兜底路径）
- AC4: 前端路由表无 /editor/:id，v1 相关组件/store/api 文件不存在
- AC5: 服务启动无报错，`mvnw compile -DskipTests` 通过

## 范围外

- Flyway DROP 四表（属"收尾装配并删除V1表"故事）
- V2 代码的 DDD 结构化
